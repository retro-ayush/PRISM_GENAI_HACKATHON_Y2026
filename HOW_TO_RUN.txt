HOW TO RUN - Interruptible Full-Duplex Voice Agent (+ VisionGuide)
===================================================================

Contents
  Part A  Run the voice agent            (steps 1-6)
  Part B  Run the tests                  (step 7)
  Part C  Run the FDB-v3 benchmark       (steps 8-13)
  Part D  Troubleshooting

All commands are run from the project folder unless a step says otherwise.
Type the commands without any "#" comments; zsh treats them as arguments.


-------------------------------------------------------------------
PART A - RUN THE VOICE AGENT
-------------------------------------------------------------------

STEP 1 - Install the prerequisites
  - Python 3.10, 3.11 or 3.12
  - uv (Python package manager):
        curl -LsSf https://astral.sh/uv/install.sh | sh
  - ffmpeg (needed only for the benchmark):
        brew install ffmpeg          (macOS)
        sudo apt install ffmpeg      (Linux)
  - A LiveKit Cloud project (free tier is enough): https://cloud.livekit.io
  - Optional: the LiveKit CLI, for simulations
        brew install livekit-cli     (macOS)

STEP 2 - Get the code and install dependencies
    git clone <repository-url>
    cd PRISM_GENAI_HACKATHON_Y2026
    uv sync                      voice agent only
    uv sync --extra vision       voice agent + VisionGuide (OpenCV, YOLO26)

STEP 3 - Configure credentials
    cp .env.example .env
  Open .env and fill in the three values from your LiveKit Cloud project
  (Settings -> API Keys):
    LIVEKIT_URL=wss://<your-project>.livekit.cloud
    LIVEKIT_API_KEY=...
    LIVEKIT_API_SECRET=...
  Then add this line so the agent joins every new room automatically:
    AGENT_NAME=
  Keep it empty for the Playground AND for the benchmark. If you leave it
  out, the agent waits for a dispatch named "fdb-agent" and never joins.

  STT, LLM and TTS all run through LiveKit Inference, so no other API keys
  are needed to run the agent.

STEP 4 - Download the model files (one time)
    uv run src/agent.py download-files
  This fetches the VAD, turn-detector and noise-cancellation models.

STEP 5 - Start the agent
  Pick one mode:
    uv run src/agent.py console    talk to it in the terminal (local mic)
    uv run src/agent.py dev        connect to LiveKit Cloud, reload on edits
    uv run src/agent.py start      connect to LiveKit Cloud, no reload
                                   (use this for the benchmark)

  To talk to it in dev/start mode, open the Agents Playground:
    https://agents-playground.livekit.io
  connect to the same LiveKit project, and enable your microphone.

  Things to try:
    "Find flights from Chennai to Delhi on October 2nd, actually make it Mumbai."
    "Book it for Priya Sharma... no wait, don't book it."
    Interrupt the agent mid-sentence with "stop, just the price."

STEP 6 - (Optional) VisionGuide, the camera extension
  Requires: uv sync --extra vision
  a) Start the agent (Step 5, dev mode).
  b) In the Agents Playground, enable BOTH camera and microphone.
     The agent picks up the camera track and starts the vision process.
     The YOLO26 weights download into models/ on first use.
  c) Ask: "Which way should I go?", "Where is my phone?",
     "Read the sign in front of me.", "Guide me to the chair."
  The annotated view appears in the Playground as the agent's video track.

  Without LiveKit (local webcam only):
    uv run python vision_guide/vision.py
  This writes vision_guide/scene.json, which the agent reads when no
  LiveKit camera is connected.

  Useful settings in .env (all optional):
    VISION_MODE=livekit | fake | off
    VISION_DEVICE=auto | mps | cuda:0 | cpu
    MOCK_LATENCY_PROFILE=instant | fast | normal | slow | realistic

  After any session, print a latency / interruption / vision report:
    uv run python scripts/report.py
    uv run python scripts/report.py --timeline

PART B - RUN THE TESTS
-------------------------------------------------------------------

STEP 7 - Unit tests and simulations
  Offline unit tests (coordinator, vision, tools, overlay):
    uv run pytest

  Lint and format:
    uv run ruff check
    uv run ruff format

  Conversation simulations (uses LiveKit Cloud and spends inference credits;
  the lk CLI does not read .env, so load it first):
    set -a; source .env; set +a
    lk agent simulate text --scenarios scenarios.yaml

PART C - RUN THE FULL-DUPLEX-BENCH v3 BENCHMARK
-------------------------------------------------------------------

How it works: the harness streams 100 recorded audio queries into LiveKit
rooms named "eval-xxxx". Our agent joins each room, answers, and logs every
tool call to /tmp/agent_tool_calls.log. The harness records the reply,
transcribes it, and scores tool calls, arguments, pass rate and latency.

The agent and the harness MUST run on the same machine, because the
harness reads the tool calls from that local log file.

STEP 8 - Get the harness (one time)
  From the project folder (Full-Duplex-Bench/ is already git-ignored):
    git clone https://github.com/DanielLin94144/Full-Duplex-Bench.git
    cd Full-Duplex-Bench/v3

STEP 9 - Create a separate Python environment for the harness (one time)
  The harness needs different package versions from the agent, so give it
  its own venv. Do this inside Full-Duplex-Bench/v3:
    python3 -m venv .venv
    .venv/bin/pip install --upgrade pip
    .venv/bin/pip install "livekit-agents~=1.3" "livekit[crypto]~=1.0" numpy \
        python-dotenv pydub ffmpeg-python openai "nemo_toolkit[asr]" gdown

STEP 10 - Download the benchmark data (one time, ~736 MB)
  Still inside Full-Duplex-Bench/v3:
    .venv/bin/gdown 1SO_4MTazWQ_jvCx0dtmpQ-t40bdd07yz -O fdb_v3_data.zip
    unzip -q fdb_v3_data.zip -x '__MACOSX/*'
    rm fdb_v3_data.zip
  You should now have fdb_v3_data_released/ with 100 folders, each holding
  input.wav and metadata.json.
  (If gdown fails, download it in a browser from the Google Drive link in
  Full-Duplex-Bench/v3/README.md and unzip it here.)

STEP 11 - Configure the harness (one time)
  a) Create Full-Duplex-Bench/v3/.env.local with:
       LIVEKIT_URL=...          same three values as the project's .env
       LIVEKIT_API_KEY=...
       LIVEKIT_API_SECRET=...
       OPENAI_API_KEY=sk-...    used by the gpt-4o judge in the scoring step

  b) macOS / no NVIDIA GPU only: the harness always moves its speech-to-text
     model to CUDA and crashes without it. Patch it once:
       .venv/bin/python - <<'EOF'
       p = "run_tool_benchmark.py"
       s = open(p).read()
       s = s.replace("    if hasattr(model, 'cuda'):",
                     "    import torch\n    if torch.cuda.is_available():")
       open(p, "w").write(s)
       print("patched")
       EOF

STEP 12 - Run the benchmark (two terminals)
  TERMINAL 1 - start the agent, from the project folder:
    rm -f /tmp/agent_tool_calls.log
    uv run src/agent.py start
  Leave it running. Check that .env has AGENT_NAME= (empty), and that no
  other agent on the same LiveKit project (e.g. one deployed to LiveKit
  Cloud) is also joining rooms.

  TERMINAL 2 - run the 100 samples, from Full-Duplex-Bench/v3:
    .venv/bin/python run_tool_benchmark_all_released.py --provider interruptible
  The first run downloads the speech-to-text model (~600 MB). Results are
  saved per sample as result_interruptible.json; re-running skips finished
  samples, so you can stop with Ctrl-C and resume. Add --force to redo all.

STEP 13 - Score the run
  When all 100 samples are done, stop the agent (Ctrl-C in Terminal 1),
  then in Terminal 2 (Full-Duplex-Bench/v3):

    .venv/bin/python evaluate_tool_calls.py --benchmark benchmark_data_v2.json --results-dir fdb_v3_data_released --provider interruptible --output interruptible_evaluation_report.json --use-llm

    .venv/bin/python evaluate_pass_rate.py --benchmark benchmark_data_v2.json --results-dir fdb_v3_data_released --provider interruptible --output interruptible_pass_rate_report.json --use-llm

    .venv/bin/python analyze_tool_latency.py --results-dir fdb_v3_data_released --provider interruptible

  Reports (in Full-Duplex-Bench/v3/):
    interruptible_evaluation_report.json  tool selection F1, argument and
                                          response accuracy
    interruptible_pass_rate_report.json   strict pass/fail per sample
                                          (the "task completion" number)
    interruptible_latency_report.json     first-response, tool-call and
                                          task-completion latency

PART D - TROUBLESHOOTING
-------------------------------------------------------------------

The agent never joins the room / benchmark gets no reply
  -> .env must contain AGENT_NAME= (empty). Restart the agent after editing.

"Missing credentials ... OPENAI_API_KEY"
  -> Add OPENAI_API_KEY to Full-Duplex-Bench/v3/.env.local (Step 11a).

"Results directory not found: fdb_v3_data_released"
  -> Data not downloaded, or you are not inside Full-Duplex-Bench/v3 (Step 10).

"source: no such file or directory: .venv/bin/activate"
  -> The harness venv was not created (Step 9). The commands above call
     .venv/bin/python directly, so activating is not required.

"Torch not compiled with CUDA enabled"
  -> Apply the patch in Step 11b.

"unrecognized arguments: # ..."
  -> A comment was pasted along with the command. Remove everything after #.

"pyenv: uv: command not found" or "pyenv: version '3.12' is not installed"
  -> uv was installed with pip inside a pyenv Python. Either install the
     standalone uv (Step 1), or prefix commands with the pyenv version that
     has uv, e.g.  PYENV_VERSION=3.13.0 uv run src/agent.py start

Tool calls missing from benchmark results
  -> The agent and harness must run on the same machine, and the agent's
     AGENT_TOOL_LOG must stay at its default /tmp/agent_tool_calls.log.

VisionGuide: "vision extra not installed" warning
  -> uv sync --extra vision
